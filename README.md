# P2S Workspace (Fabric 1.21.x)

P2S Workspace 是一个把 Minecraft 结构编辑做成“聊天式工作流”的 Fabric 模组：先选区、再建立项目和工作区、然后让 AI 提交 patch 预览，最后由你决定是否应用到世界。

## 安装前提

- 客户端与服务端都安装本模组；单人模式下也需要让当前游戏环境加载模组本体。
- 当前仓库维护的目标版本是 `1.21` 与 `1.21.1`。
- 需要为 AI 接口配置可用的 `apiUrl`、`apiKey`、`model`。

## 快速上手

1. 先在客户端配置 LLM：可直接编辑 `config/p2s_client.json`，也可进入游戏后在配置界面调整。
2. 进入世界后，按 `O` 打开聊天面板。
3. 使用选区物品框定一个区域：
   - 默认物品是 `minecraft:spectral_arrow`
   - 左键设置 `pos1`
   - 右键设置 `pos2`
4. 在聊天面板里创建或打开项目。
5. 选择一个工作区文件，向 AI 描述你要建造或修改的内容。
6. 查看 patch 预览，决定 `Apply` 或 `Discard`。
7. 需要回退时，可使用 `Undo`、`Redo`、`Checkpoint` 和会话恢复功能继续迭代。

## 日常使用流程

### 1. 选区

选区决定了项目的工作范围。通常先完成选区，再创建项目；之后的工作区编辑与补丁预览都会围绕这个范围展开。

### 2. 项目与工作区

- 一个项目可以包含多个工作区文件。
- 你可以在聊天界面里切换、创建、重命名或删除工作区文件。
- 左侧编辑区支持 `State / Script / Diff` 三个 Tab，用来查看当前状态、可编辑工作区正文和差异。

### 3. 聊天与补丁预览

- 发送消息后，AI 会基于当前项目和工作区提出修改方案。
- 修改不会直接落地到世界，而是先生成预览。
- 只有在你点击 `Apply` 之后，补丁才会真正应用。
- 如果结果不合适，可以 `Discard`，并继续让 AI 调整。

### 4. 会话恢复与检查点

- 当前项目的聊天会话会尽量自动恢复，方便连续编辑。
- 可以创建检查点，便于在多个版本之间来回试验。
- 适合用来做“先试一个方案，不满意再回滚”的迭代工作流。

## 配置说明

### 客户端配置：`config/p2s_client.json`

主要用于：

- 配置客户端 LLM 接口
- 修改选区物品
- 调整 patch 预览限制、确认阈值、会话超时等运行参数
- 控制流式输出、自动应用、上下文压缩等客户端行为

当前已经没有单独的服务端配置文件；用户可编辑的配置项都归到客户端配置中。

## 数据与备份

如果你想迁移环境、做备份或排查问题，优先关注这些路径。除 `config/p2s_client.json` 外，其余都是项目/会话数据目录，不是服务端配置项：

- `config/p2s_client.json`
- `config/p2s_projects_v2/`
- `config/p2s_sessions_v2/`
- `config/p2s_skills/`
- `config/p2s_storage/`

## 常见问题

### 为什么聊天面板打不开？

先确认按键是否是 `O`，并确认客户端已经正确加载模组。

### 为什么联机里不能正常用？

多人游戏下，客户端与服务端都需要安装本模组；缺少任意一侧时，项目、工具桥接和会话相关能力都不能正常工作。

### 为什么 AI 没有直接修改世界？

当前流程是“先提 patch，再由玩家确认”。看到预览后，需要手动点击 `Apply` 才会真正应用到世界。
